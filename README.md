# REMATCH

손흥민이 벤치에 있던 그 밤을, 당신이 다시 지휘한다.

실제 월드컵 명승부의 결정적 순간에서 경기를 이어받아, 전술 개입으로 결과를 다시 쓰는 미션형 시뮬레이터입니다. DAKER 월간 해커톤 「내가 축구 감독이라면, 월드컵 전술 웹서비스 챌린지」 출품작입니다.

## 실행 방법

사전 요건은 Node.js 22 이상입니다. 개발에는 Node 24.18.0을 사용했습니다.

```bash
npm install
npm run dev        # 개발 서버
npm run test       # 단위 테스트와 종료 경로 fixture
npm run typecheck  # 타입 검사
npm run build      # 정적 번들 산출 (dist/)
npm run preview    # 산출된 번들 로컬 확인
npm run smoke      # 빌드된 번들의 전체 라우트 렌더 검사
npm run e2e        # 실제 브라우저에서 경기 루프 종단 검사
npm run verify     # 위 전부를 순서대로 실행하는 배포 전 관문
```

## 현재 구현 상태

**동작하는 것**: 다섯 시나리오, 이어받는 시점부터 분 단위로 흐르는 경기 시계와 재생 제어(일시정지, 1배속과 2배속과 4배속, 끝까지 건너뛰기), 더그아웃 드래그 편집(프리셋 슬롯 사이 이동과 교환, 벤치 교체 카드), 팀 지시 다섯 축, 개입 토큰 세 개와 변화 없는 확정 거절, 관측 지연과 예산과 쿨다운을 가진 상대 AI 반격, 경기 형식 상태기(정규시간, 연장, 골든골, 승부차기, 종료), 관점 상대적 종료 사실과 선언적 진출 판정, 등급 판정과 역사 대비 리포트, 매치 코드와 시드 덱 기반 새 리매치, 브라우저에만 저장되는 명예의 전당, 해시 라우팅과 없는 주소 안내 화면.

**아직 없는 것**: 실제 선발과 벤치 명단의 출처 교차검증 완료, 공유 이미지 카드, 역사 시점 표식과 분기 프롬프트, 사건별 전용 연출.

## 주요 파일

```

src/domain/engine.ts       국면 전이 상태기, 승부차기 진행, 종료 사실 파생
src/domain/simulate.ts     재개 가능한 경기 런타임. 배치와 재생이 공유하는 유일한 전이 함수
src/domain/outcome.ts      진출 판정 truth table, 등급 판정, 역사 대비
src/domain/rng.ts          worldSeed와 decision draw 분리, 매치 코드, 개입 차분
src/domain/records.ts      명예의 전당. 브라우저 저장소만 사용
src/screens/MatchRoom.tsx  경기 재생과 개입 루프
src/screens/Dugout.tsx     Pointer Events 기반 전술 편집 오버레이
src/data/scenarios/        시나리오 선언 5종
tests/fixtures/            단위 테스트와 다섯 종료 경로 fixture
scripts/smoke.mjs          라우트 렌더 검사
scripts/e2e.mjs            브라우저 종단 검사
```

## 설계에서 중요한 결정 두 가지

**경기 종료를 데이터로 선언한다.** 정규시간 종료, 연장(2026년의 완주 연장과 2002년의 골든골), 승부차기, 조별 진출 판정이 모두 `MatchFormat` 선언과 상태기로 표현됩니다. 그래서 서로 다른 종료 방식을 가진 시나리오가 코드 분기가 아니라 데이터 추가로 성립합니다. 다섯 시나리오가 `regulation`과 `extraTime`과 `goldenGoal`과 `shootout` 네 가지 결정 국면을 모두 덮는 것을 fixture가 증명합니다.

**인과가 보이는 결정론을 목표로 합니다.** 시도 단위로 고정된 `worldSeed`가 분과 팀 같은 외생 추출을 지배하고, 사용자 행동에 의존하는 추출은 따로 분리했습니다. 이렇게 하면 슬라이더를 한 칸 움직여도 미래의 난수 흐름이 통째로 바뀌지 않아, 전술 변경이 결과를 바꾼 것인지 운이 바뀐 것인지 사용자가 구분할 수 있습니다. 매치 코드는 시나리오와 시도 번호와 엔진 및 데이터 버전과 시드 검사합을 담습니다. 사용자의 개입은 담지 않으므로 정확한 계약은 같은 코드와 같은 결정이면 같은 경기라는 것이고, 코드만으로 결과가 하나로 정해진다는 뜻은 아닙니다. 새 리매치는 공개된 시드 덱을 인덱스로 전진합니다. 매치 코드에는 엔진 버전과 데이터 버전이 함께 들어가고, 버전이 다른 코드는 현재 엔진으로 조용히 재생되는 대신 거부됩니다.

**화면의 경기와 리포트의 경기는 같은 한 개의 전이 함수를 씁니다.** 재생은 그 함수를 한 걸음씩 부르고 배치 실행은 끝까지 부릅니다. 두 경로가 같은 결과를 낸다는 것은 다섯 시나리오와 개입 유무 모두에서 테스트가 단언합니다.

## 화면 아트

모든 그림은 코드 안의 인라인 SVG와 CSS로 직접 만들었습니다. 이미지 파일이 하나도 없습니다.

**생성형 AI 이미지는 쓰지 않았습니다.** 대회 요강이 허용하고 있어 검토했지만, 접근 가능한 생성 서비스의 약관이 용도를 개인 학습과 연구와 체험으로 제한하고 산출물의 지식재산권 귀속을 보증하지 않아 채택하지 않았습니다. 자세한 근거는 `src/data/SOURCES.md`에 적었습니다.

엠블럼과 선수 사진과 중계 화면과 공식 서체는 쓰지 않았고, 실제 국기도 그대로 재현하지 않았습니다. 팀 상징은 색과 추상 도형의 조합입니다.

## 제출 기획서 대비 최종 구현 차이

제출한 기획서는 개발 착수 전에 고정됐고 수정할 수 없습니다. 개발 중에 더 나은 구조를 찾거나 범위를 좁힌 곳이 있어 그 차이를 여기에 전부 적습니다. 심사자가 문서와 실물의 불일치를 스스로 발견하게 두지 않으려는 것이고, 무엇을 못 했는지도 숨기지 않습니다.

### 설계를 바꾼 것

| 기획서 | 최종 구현 | 왜 바꿨나 |
|---|---|---|
| 상태 관리 Zustand | React `useState` | 런타임 의존성을 React 둘로 줄이는 편이 정적 배포와 심사자 환경에 유리했습니다. 상태 규모도 라이브러리를 부를 만큼 크지 않았습니다 |
| 애니메이션 Framer Motion | CSS transition과 SVG | 위와 같은 이유입니다. 필요한 연출이 위치 전이와 강조뿐이라 CSS로 충분했습니다 |
| 드래그 dnd-kit 보조 | 자체 Pointer Events 제어기 (`src/ui/drag.ts`) | 피치 좌표계가 백분율 기반이라 범용 라이브러리보다 직접 제어가 단순했고, 같은 코드로 마우스와 터치를 함께 다룹니다 |

| 개입 시점에서 시드가 분기 | 세계 추출은 고정, 사용자 행동 지문은 AI 결정 추출에만 분리 | 세계를 고정해야 같은 상황에서 내 선택만 다를 때의 차이를 비교할 수 있습니다. 시드가 갈리면 결과 차이가 전술 때문인지 운 때문인지 알 수 없습니다 |
| 능력치 6축이 공격, 수비, 패스, 스피드, 피지컬, 체력 | `pace`, `passing`, `finishing`, `defending`, `stamina`, `composure` | 마무리와 침착성을 분리하고 피지컬을 뺀 편이 전술 지시 다섯 축과 더 잘 맞물렸습니다 |

| 자유 좌표 배치 | 프리셋 슬롯 사이 이동과 교환 | 임의 좌표를 허용하면 적합도 계산과 상대 대형 상성이 흔들려 슬롯 기반으로 좁혔습니다 |

### 기획서에 없었지만 넣은 것

- 개입 없이 3분이 지나면 경기를 멈추고 결정을 요구합니다. 자동 플레이테스트에서 캐주얼 사용자가 세 판 연속으로 개입을 한 번도 만나지 못하고 이탈했기 때문입니다.
- 그 화면에서 상징 선수를 한 번에 투입하는 경로를 제공합니다. 선택지가 하나뿐인 길이 없으면 탐색하지 않는 사용자는 이 게임의 핵심 행동에 끝내 도달하지 못합니다. 지금 상징 선수가 선언된 경기는 남아공전 하나이므로 이 버튼도 그 경기에만 나옵니다.
- 더그아웃이 확정 전에 지금 전술이 계수상 얼마나 센지 미리 보여주고, 포메이션을 바꾸면 무엇이 바뀌었는지 줄 수로 말합니다.
- 결과 리포트가 내가 바꾼 것과 왜 이렇게 끝났는지와 다음에 무엇을 바꿀지를 결과 바로 뒤에 놓습니다.
- 의도적으로 넣은 균형 보정 두 가지를 도움말과 출처 대장에 공개합니다.

## 데이터 출처와 라이선스

경기 결과와 일정과 선수명 같은 사실 정보만 사용했고 공개 보도와 공개 기록을 참고해 직접 재구성했습니다. 사실 정보 자체는 저작권 보호 대상이 아닙니다.

FIFA와 각 연맹과 구단의 엠블럼, 선수 사진, 중계 영상, 공식 폰트는 일절 사용하지 않았습니다. 국기와 유니폼 표현은 자체 제작한 인라인 SVG 도형입니다.

모든 시나리오는 실존 인물과 팀에 대한 헌정과 존중의 톤으로 작성했습니다. 특정 선수나 팀이나 국가를 비하하는 표현은 포함하지 않습니다.
